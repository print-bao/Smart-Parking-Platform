
# Smart Parking Platform - Stakeholder Analysis and Charters

## 1. Stakeholder Analysis
The stakeholder analysis identifies the people and groups that are inolved in the Smart Parking Platform. The stakeholders are organized using a Power-Interest Grid based on the level of their influence and their interest in the project. This helps determine how each stakeholder would be managed and their communication throughout the development of the platform.

### 1.1 Power-Interest Grid
| Stakeholder | Power | Interest | Category |
|---|---|---|---|
| Parking Facility Operators | High | High | Manage Closely |
| System Administrators | High | High | Manage Closely |
| Finance / Billing | High | High | Manage Closely |
| City Transportation Departments | High | Low | Keep Satisfied |
| Drivers / Vehicle Owners | Low | High | Keep Informed |
| Mobile Application Users | Low | High | Keep Informed |
| Third-Party Payment Providers | Low | Low | Monitor |

![Power-Interest Grid](assets/images/Power_Interest_Grid.png)

### 1.2 Stakeholder Management

#### Manage Closely
Parking facility operators, system administrators, and finance/billing will regularly receive project updates and be involved in reviewing requirements and development progress. Their feedback will help support that the system meets its operational requirements.

#### Keep Satisfied
The city transportation departments will be receiving important updates about project progress and any changes that may affect parking operations or regulations.

#### Keep Informed
Drivers and mobile application users will be informed about system features, updates, and changes that may affect their parking experience. Feedback from users will help identify any improvements needed.

#### Monitor
Third-party payment providers will be monitored for any service changes, availability issues, or integration problems that could potentially affect the project.

## 2. Project Charter

### 2.1 Project Overview

The Smart Parking Platform is a software system that is designed to help drivers locate, reserve, and pay for available parking spaces in parking garages. The system will also provide parking facility operators with tools to manage garage information, monitor parking occupancy, and generate reports.

The project is being developed by $oftware ¢orp. to improve parking accessibility and provide a centralized system for drivers and parking facility operators.

### 2.2 Project Objectives

1. Provide drivers with real-time parking availability.
2. Allow drivers to reserve and pay for parking spaces.
3. Provide parking facility operators with garage management tools.
4. Support reporting for parking occupancy and financial information.
5. Improve the overall parking experience for drivers and operators.

### 2.3 Project Scope

The Smart Parking Platform includes the following components:

1. Authentication
2. User and Operator Setup
3. Garage Monitoring
4. Payment Processing
5. Reporting

These components will allow drivers and parking facility operators to interact with the system and manage parking-related activities.

### 2.4 Project Stakeholders

The primary stakeholders include:

- Drivers / Vehicle Owners
- Parking Facility Operators
- System Administrators
- City Transportation Departments
- Finance / Billing
- Third-Party Payment Providers

### 2.5 Project Timeline

The project follows a 12-week development timeline outlined in the Work Breakdown Structure and Gantt chart.

| Project Component | Planned Weeks | Duration |
|---|---|---|
| Authentication | Weeks 1-3 | 3 Weeks |
| User and Operator Setup | Weeks 2-5 | 4 Weeks |
| Garage Monitoring | Weeks 4-8 | 5 Weeks |
| Payment | Weeks 6-9 | 4 Weeks |
| Reporting | Weeks 8-12 | 5 Weeks |

### 2.6 Project Deliverables

The major project deliverables include:

1. Web and Mobile Applications
2. Backend/API Services
3. Mapping and Location Integration
4. Garage Monitoring
5. Payment Processing
6. Reporting Functionality

### 2.7 Project Constraints

The project must be completed within the semester timeline. Development is also dependent on third-party services and APIs for certain features.

The system must follow applicable security, privacy, and regulatory requirements to protect user information and payment transactions.

### 2.8 Project Management

The Project Manager will coordinate development teams, monitor project progress, manage risks, and ensure project deliverables are completed according to the development schedule.

## 3. Team Charter

### 3.1 Team Purpose

The purpose of the development teams is to coordinate and complete the Smart Parking Platform while meeting the project's requirements and development schedule.

Each development team will be responsible for specific components of the system and will work together to ensure successful integration.

### 3.2 Team Roles and Responsibilities

| Team | Responsibility |
|---|---|
| Mobile Application Team | Develop the mobile application for drivers. |
| Web Application Team | Develop the web interface for drivers and parking facility operators. |
| Backend/API Team | Develop backend processes and API integrations. |
| Mapping & Location Services Team | Manage mapping, navigation, and location services. |
| Payment Integration Team | Develop payment processing functionality. |
| QA & Testing Team | Test the system and identify development issues. |
| Project Manager | Monitor project progress, risks, and team coordination. |

### 3.3 Team Communication

Each development team will meet weekly to review progress, development issues, and upcoming tasks.

GitHub will be used for project documentation and updates, while Trello will be used to track backlog items, sprint tasks, and development progress.

Progress reports will summarize completed work, current issues, and upcoming tasks.

### 3.4 Decision-Making

Development teams will coordinate important technical decisions with the Project Manager to ensure project requirements and deadlines are met.

Decisions that affect multiple development teams will be discussed to identify possible dependencies and minimize project delays.

### 3.5 Conflict Resolution

Any issues between development teams will be discussed during team meetings. Unresolved issues will be brought to the Project Manager to determine an appropriate solution.

### 3.6 Team Goals

1. Complete assigned development tasks.
2. Maintain communication between development teams.
3. Identify and minimize project risks.
4. Meet project deadlines.
5. Ensure the Smart Parking Platform meets its requirements.
